## Confirmed blockers

### P1 — D3: an active model request can be reaped as idle

Evidence: [`model_server.py`](../apps/api/deckastra_api/model_server.py), `_reap`, `ensure_ready`, `_KeptAlive.complete` (approximately lines 175–289).

`_KeptAlive.complete()` refreshes last-use only before invoking the inner client. `_reap()` checks elapsed time without an in-flight-request guard. A call lasting longer than the idle window can therefore lose its runtime while working. Repeated short calls are not a sufficient regression test for one long call.

Reproduced using the existing fake-runtime fixture, a one-second idle window and a 1.6-second inner call: the runtime had exited before the call returned. No weights or paid model were used. Reproducer: `.next/test_d3_review_20260916.py` (local, ignored test artifact).

Remaining work: track active requests under the supervisor lock and update idle time at completion in a `finally` path. Verify restart also refreshes the client's endpoint: `ensure_ready()` returns a URL, but the wrapper currently discards it while the inner client retains its previous URL.

Acceptance: a single request longer than idle survives; an idle runtime still unloads; success/failure/cancellation release activity; a retained client works after idle shutdown and restart.

### P1 — D5: an old version can acknowledge away unsent work

Evidence: [`routes.py`](../apps/api/deckastra_api/routes.py), `mark_reconciled` around lines 922–969; [`sync.py`](../apps/api/deckastra_api/sync.py), `reconciled` around line 558.

The route checks only that the supplied version belongs to the deck. The service allows the matching outbox row to be absent, then supersedes all pending/blocked rows. Supplying the pre-divergence base version, without making a merge, returned HTTP 200 with `retired: 2` and `state: "in_sync"` in the review test. The document remains locally, but the changes are no longer owed to the server: this is silent loss from synchronization.

Acceptance: refuse a pre-conflict version, a version without a pending resolving transaction, and an acknowledgement for a different conflict. Leave the outbox untouched on refusal. Tie acknowledgement to a verified resolution and remote base, not merely any historical version ID.

### P1 — D5: an edit after the merge is also retired

The same service supersedes every pending/blocked row except the named merge. Reproducer: commit merge M, commit a later title edit N, then acknowledge M. Response: HTTP 200, `retired: 3`, one pending row. N should still be owed, or the stale acknowledgement should be refused.

Remaining work: introduce an explicit conflict/resolution boundary and an atomic commit/acknowledgement contract. Retire only what the resolution incorporates. Preserve changes after that boundary, including edits made by another window or MCP client.

Acceptance: delayed acknowledgement cannot discard post-merge work; crash/retry is idempotent; concurrent writers cannot change the retirement boundary unnoticed. Review pending assets as part of this correction: `reconciled()` currently retires pending asset rows too, although the merged document may still require their bytes.

Both D5 cases were reproduced in `.next/test_d5_review_20260916.py`, reusing the existing isolated SQLite fixtures. These were review checks, not production edits.

## D3: correct the starting point and the evidence standard

Already implemented:

- [`router.py`](../agents/deckastra_agents/router.py): explicit local/cloud selection and no Anthropic fallback on the explicit local branch.
- [`local_model.py`](../agents/deckastra_agents/local_model.py): `LlamaServerClient`, JSON-schema response requests and provider usage accounting.
- [`model_packs.py`](../agents/deckastra_agents/model_packs.py): directory/manifest discovery and actionable missing/invalid/ambiguous-pack refusal.
- [`nodes/_common.py`](../agents/deckastra_agents/nodes/_common.py): authoritative Pydantic validation, at most two attempts and `structured_requests` observations.
- [`model_server.py`](../apps/api/deckastra_api/model_server.py): runtime lifecycle; [`benchmark-model-pack.py`](../scripts/benchmark-model-pack.py): actual story-node benchmark.

`CLAUDE.md` records six historical Qwen3-4B-Q4_K_M story runs: 5/6 first-pass validity, median 248 seconds, peak RSS 4,432 MB. This review did not rerun those measurements or verify their raw result artifacts. They establish neither whole-deck latency nor broad quality. The stated 15–20 minute full-deck figure is an extrapolation, not a measured end-to-end result. An 83% first-pass result from six runs and two briefs is encouraging preliminary evidence, not a release-quality conclusion.

The benchmark checks invented citation **IDs**. Valid IDs do not prove that the cited source supports a claim. Add held-out factual-support and coverage evaluation. Thermals and sustained throughput are separate measurements; the present harness's RSS counter is not a thermal test.

Missing usage is explicitly warned about but charged as zero. That avoids fabricated counts, but leaves the token ceiling incomplete. Decide whether unknown usage should stop the run or receive explicitly marked conservative budget treatment; do not present that run's zero as measured consumption.

Benchmark 7–8B only as a measured device configuration (including partial offload, context and concurrency). One model failing one schema would reject that model/configuration or task allocation, not prove local generation categorically impossible. Packaging, model settings/download management, full-graph behavior and target-Mac measurements remain separate gates. No download was performed.

## D4: do not rebuild the engine

[`transition/compile.ts`](../packages/animation-engine/src/transition/compile.ts), pairing/delta/sample/CSS modules and [`PresentMode.tsx`](../packages/editor-ui/src/components/PresentMode.tsx) already implement the proposed two-scene path. Transition time starts with incoming-slide arrival, separately from slide entrances; mappings pass through the renderer. Explicit pairing and opt-in automatic pairing are implemented. [`motion.py`](../apps/api/deckastra_api/motion.py) already contains cross-slide `plan_transition`.

[`MotionPanel.tsx`](../packages/editor-ui/src/components/MotionPanel.tsx) now supports preset expansion into keyframes, keyframe edits, gesture commits, trim, split and ripple. Timeline conflict helpers, backward-navigation tests and `fitToDisplay` exist. This is substantially beyond the pasted description of number fields and buttons.

The current animation suite covers transition compilation/pairing/fixtures, timeline authoring/conflicts and deck acceptance. UI tests cover gestures, transitions, navigation and display fitting. These do not substitute for a measured Electron drag cadence, actual painted-frame parity or physical projector/macOS verification.

PPTX exports explicitly approximate Morph with fade while supplying paired names; see [`export-pptx/src/index.ts`](../packages/export-pptx/src/index.ts) and the corresponding tests. Matching XML names is not proof that PowerPoint visually performs the intended native Morph. Keep that limitation visible.

Recommended next D4 work: exercise the current built application and close measured acceptance gaps, rather than opening D4.1 as greenfield implementation.

## D5: retain the slices, revise the contracts

The replay spike exists in [`test_sync_replay.py`](../apps/api/tests/test_sync_replay.py). Its main equality assertion compares `slides`, not `serializeDocument()` byte identity for the entire document. Versions deliberately receive different storage IDs. Expand evidence to canonical whole-document content, inverse application and asset resolution before describing this as the original full byte-equality gate passing.

A failed replay onto a **diverged** base does not force snapshot-only sync. Ordered operations can still synchronize against explicit ancestry, with conflict resolution or rebasing where appropriate. Same-base determinism and divergent-base merge behavior are different requirements.

The implemented outbox uses `change_key`, not identical local/remote version IDs. This is a reasonable identity mapping choice, but a stable source version ID could also serve as an idempotency key if the receiver stored it. Different server-generated version IDs alone do not make version-based deduplication impossible. What matters is durable receiver-side enforcement, scoped identities and rejection of the same key with different content.

`sync.drain()` currently receives an injected `send` callable; the repository search found calls in tests rather than a production synchronization loop. A passing fake sender proves local queue behavior, not remote idempotency, authorization or convergence. Before wiring a real sender, define remote-parent/version mapping, atomic receiver commit plus receipt, replay after lost responses, bootstrap/pull and conflict retries.

Workspace-origin isolation and membership-cache policy already exist. The latter allows stale cached membership within documented windows; that is an offline policy, not proof that a revoked member is denied by a live server. The eventual remote receiver must check current membership independently on every operation.

Assets are queued before referring changes and share links can pin versions (`test_pinned_presenting.py`). Still needed: real content transfer/hash verification, deletion/tombstone and retention semantics, and a fresh client presenting a pinned version with all assets. A storage key in an outbox is not itself delivery of bytes.

Keep live co-editing explicitly outside this milestone. The user-facing conflict panel, authenticated cloud workspace onboarding and two-device offline/reconnect journey remain the product work after the protocol is safe.
