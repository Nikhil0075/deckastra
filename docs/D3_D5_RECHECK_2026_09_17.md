## Remaining findings

### P1 — A pre-conflict queued edit can still masquerade as a resolution

Location: [`sync.reconciled`](../apps/api/deckastra_api/sync.py), approximately lines 600–636.

The new check compares the resolving row's creation position with the **blocked change's creation position**, not with an actual conflict/resolution record. A later offline edit can predate the server refusal yet pass this check.

Reproduced with the existing `diverged` fixture: its first offline edit is refused and its second offline edit remains pending. Without committing any merge, acknowledge the already-existing head version. The endpoint returns HTTP 200, retires the blocked row and reports `waiting`. The queued head contains only the later transaction's operations; it is not a merged replacement containing every superseded change. This can discard earlier unsent operations from synchronization.

Reproducer: `.next/test_d5_followup_20260917.py`, `test_pre_refusal_queued_version_is_not_a_resolution` — failed, expected 409, received 200 with `retired: 1`.

**Required:** bind a resolution to the current conflict identity, remote base and a verified pending resolution transaction. Its operations must represent the resolved state relative to the remote base, rather than an arbitrary local delta. Enforce this atomically with retirement. Add rejection tests for an existing queued head, stale conflict acknowledgements and previously sent/superseded resolution rows. Preserve all work when refusing.

### P1 — Rejected project adoption still imports into that project

Location: [`bootstrap.adopt`](../apps/api/deckastra_api/bootstrap.py), project loop around lines 118–128; `_adopt_project` around lines 187–207.

`_adopt_project()` records a refusal when the ID already belongs to a different workspace, then returns `None`. Its caller nevertheless calls `_pull_decks()` with the rejected ID. Remote decks are consequently inserted into the existing local project, despite the reported refusal.

Reproduced by making the captured remote project's ID match the device's personal project. The report simultaneously contained “already in another workspace” and a nonempty `decks_pulled` list.

Reproducer: `.next/test_bootstrap_review_20260917.py`, `test_rejected_project_cannot_receive_remote_decks` — failed.

**Required:** return an explicit adoption result and skip all descendant reads/writes on refusal. Test that the local project's decks and outbox remain unchanged, and that no remote deck fetch occurs for the refused project. This is an isolation invariant, even though accidental generated-ID collisions are unlikely.

### P2 — HTTP bootstrap silently stops at 200 decks per project

Location: [`HttpRemote.presentations`](../apps/api/deckastra_api/bootstrap.py), approximately line 344; [`list_presentations`](../apps/api/deckastra_api/routes.py), approximately line 615.

The adapter makes one request without a limit or cursor. The route defaults to 200 rows and caps requests at 500; it exposes no continuation in this response. A larger project therefore appears successfully pulled with older decks absent. Raising the limit alone would merely move the truncation boundary.

**Required:** stable pagination and a complete pull loop, with resumable/error-aware reporting. Acceptance: a project larger than both limits arrives completely, without duplication or lost rows across pages. This finding is established by code inspection; a 201-deck runtime reproduction was not run.
