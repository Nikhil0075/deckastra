# 01 — Multilingual decks, step narration and sound

Status: built, 2026-10-03 (planned 2026-10-01). What follows is the plan as
written; this block says where the build differs from it and what is still open.

**Built and checked in the desktop app** (acceptance steps `languages` and
`narration`, isolated profiles): locale overlays with the switcher, editing
through the lens and outdated detection; translation as a proposal with
protected spans and a glossary; narration per click step with per-language
takes, recorded through the microphone (Chromium's fake device in the harness),
voiced, or chosen from the deck's other audio files, each with a volume trim;
"Say names as" pronunciations, sent to Google as SSML `<sub>`; the narrated
deck advancing on its own in present mode; the sound library, uploads and the
Audio lanes with waveforms decoded from the files; Indic, Arabic and Hebrew
faces with right-to-left; locale-aware PDF and PPTX with narration in the
PowerPoint; shared links that open in a language (`?lang=`) and load their
pictures and recordings; MCP `locale_list`, `locale_add`, `locale_propose` and
`narration_propose`.

**Differs from the plan:**
- Google voices return **MP3**, not Ogg Opus: PowerPoint cannot carry Opus, and
  one format avoids keeping a second copy. Uploaded Ogg is still measured.
- Pronunciations are a **per-person** preference, not a per-workspace lexicon.
- Volume trims down only (0 to −30 dB): playback and PowerPoint both cap at the
  file's own level, so a boost would be a number that does nothing.
- Waveforms are decoded from the file in the editor rather than read from the
  peaks stored at upload, which the document does not carry.
- No HTTP route adds an empty language; the editor and `locale_add` both build
  the same operation (`language_routes.py` says why).

**Open:**
- **Google is verified live, once, on 2026-10-03** (project `deckastra`,
  connected by `scripts/setup-google-cloud.ps1`): `scripts/check-google-cloud.py`
  translated into Hindi with a protected number kept, listed 46 hi-IN voices
  and voiced a line with a pronunciation (MP3, 1968 ms measured, matching its
  size at 32 kbps); the desktop `languages` step translated a deck through
  Cloud Translation and exported its PDF, and `narration` voiced four lines
  with Chirp 3 HD and put them in a PowerPoint. That run found a masking bug
  the stand-in could not: a digit inside a word ("Q3") was split out, and
  Google read "Q⟦1⟧" as "first quarter". Such words are now kept whole. The
  contract tests (`test_google_providers.py`) still run without Google.
- **CJK faces are not bundled.** They are the downloadable packs of 04 §7,
  which needs the hosting that plan builds. Until then Japanese, Korean and
  Chinese draw in the operating system's face; a Japanese PDF from Windows was
  checked to carry real, extractable glyphs (`test_language_exports.py`).
- Of the SSML subset, `<sub>`, `<phoneme>` (IPA between slashes in "Say names
  as") and `<break>` (`[pause]` markers) are produced, and the speaking rate is
  a control; `<prosody>` pitch and `<say-as>` are not offered.
- **PDF text in Arabic** is exact for readers that honour `/ActualText`
  (Poppler, Acrobat, pdf.js); a reader that uses only the character map
  (pypdf, pdfplumber) gets the letters with blanks where Noto Arabic draws a
  letter as a shared base plus a dot. Hindi reads back whole either way.

Closed by the 2026-10-03 recheck: pronunciation changes now re-voice exactly
the affected lines; Play honours a take's volume; inline italics follow the
script rules; orphaned cues raise W323 in the document validator; Hindi PDF
text extracts without blanks.
Related: [05 image localization](05_IMAGE_TEXT_LOCALIZATION.md) reuses the locale
overlays defined here; [04 GCP](04_GOOGLE_CLOUD_PLATFORM.md) hosts the
translation and speech services; [02 Gemma/ADK](02_GEMMA_ADK_ASSISTANT.md) can
propose translations locally.

## 1. What is being asked

1. One deck, many languages. A person switches the deck (editor, present mode,
   export) between languages without keeping N copies of the deck.
2. Narration that belongs to the timeline. A slide with three click phases gets
   three narration clips, one per phase, and each plays when its phase plays.
3. A library of predefined sound effects, plus the person's own audio, placed on
   the timeline.
4. Narration in every language the deck has, generated by text-to-speech or
   recorded.

## 3. Design decisions

### 3.1 A language is an overlay, not a copy

A copy per language makes every layout fix N fixes. An overlay keeps one
geometry and one mutation path.

```ts
// packages/presentation-schema/src/locales.ts (new)
LocaleOverlay = {
  locale: string,                 // BCP-47, "hi-IN"
  status: "draft" | "reviewed",
  direction?: "ltr" | "rtl",      // default from the locale
  fonts?: Partial<Record<"heading" | "body" | "mono", string>>, // per-script override
  entries: Record<TextTargetPath, LocaleEntry>,
}
LocaleEntry = {
  value: RichTextDocument | string,   // same shape as the source slot
  sourceHash: string,                 // hash of the source text it was translated from
  origin: "human" | "machine" | "agent:<id>",
}
PresentationDocument.locales?: Record<string, LocaleOverlay>
```

- **Keys are id-addressed paths into text slots**, e.g.
  `/slides/id:sld_x/elements/id:el_y/content`, `/slides/id:sld_x/speakerNotes`,
  `…/altText`, chart category labels, table cells, and narration cue text (§3.3).
  An allowlist decides which paths may be overlaid, the same way
  `isAllowedBindingTarget` restricts bindings. An overlay can never move,
  recolour or retype anything; it only replaces words.
- **Why a `sourceHash`:** when someone edits the source sentence, that entry is
  *outdated*, not wrong. The Languages panel shows "4 outdated" and offers to
  re-translate only those. No timestamp comparison is needed.
- **Applying a locale** is `localeOperations(doc, locale): PatchOperation[]` in
  `packages/presentation-core` (core never returns a modified document). Callers
  apply those operations to a **copy** through `packages/transactions` and build
  the scene from the copy. Editing the document while a locale is showing edits
  the *overlay entry*, not the source (§3.2).
- **Which locale is showing is editor or session state**, like zoom and selection.
  It is never saved in the document. Exports and share links take a `locale`
  parameter.
- **Validation (new rule codes in `RULES`, `validate.ts`):**
  - E3xx: an overlay path outside the allowlist, or a value of the wrong shape
    for the slot.
  - W3xx: an overlay entry whose target no longer exists (stale, but kept on
    round-trip, the same way W240/W241 preserve unknown content).
  - W3xx: an outdated entry (its `sourceHash` differs), reported, not refused.
  - `REQUIRES_RENDER_CONTEXT`: per-locale overflow (W103) and font coverage (a
    glyph the chosen face does not have).

**Python side.** Overlays are ordinary document data, and applying one uses
standard operations, so `apps/api/deckastra_api/patch.py` needs no new op code.
Add a conformance case to `apps/api/tests/test_patch_conformance.py` anyway,
because rich-text replacement inside a locale entry is a new shape. Generated
JSON Schema picks up the new types through `npm run schema:emit`.

### 3.2 Editing in a language

- AppBar gets a **language switcher** (`shell/AppBar.tsx`, new `LanguageMenu.tsx`):
  the source language, each overlay, and "Add language…".
- While a non-source locale is showing:
  - text edits in `TextEditor.tsx` and the inspector write
    `/locales/<l>/entries/<path>` (an `add` or `replace`), with ordinary undo;
  - geometry edits still write the shared geometry, and the UI says so:
    "Moving this moves it in every language";
  - Design Check runs against the localized scene, so overflow in Hindi is a
    Hindi finding.
- A **Languages panel** (new `components/LanguagesPanel.tsx`, in AI mode or
  Design mode) lists locales with "translated / outdated / missing" counts,
  **Translate missing**, **Re-translate outdated**, and a side-by-side review
  (source | target, per slide), built on `FinalFrameSlide` like the proposal
  cards.

### 3.3 Narration belongs to a click step

```ts
// on Slide (document.ts)
narration?: {
  cues: NarrationCue[],
}
NarrationCue = {
  id: Id,                // "nar_…"
  step: number,          // segment index: 0 = on arrival, 1 = after click 1, …
  text: string,          // source-language script; overlays translate it
  takes?: Record<string /* locale */, NarrationTake>,
}
NarrationTake = {
  assetId: Id,           // kind 'audio'
  durationMs: number,    // measured from the file, not from the TTS request
  voice?: string,        // "hi-IN-Chirp3-HD-…" or "recorded"
  textHash: string,      // the script this audio says; stale if the text changes
  gainDb?: number,
}
```

- **Three phases give three cues.** The editor derives the step count from the
  compiled timeline (`compileTimeline(...).segments`). A slide with click
  reveals A, B and C has segments {arrival, A, B, C}. The panel offers one cue
  per segment and hides the empty "arrival" cue unless the author wants one.
  If animation clicks are added or removed, cues whose `step` no longer exists
  are shown as orphaned (a W-rule). They are not deleted.
- **Script from notes.** "Split notes into narration" splits speaker notes on
  paragraphs, one per step, as a starting point.
- **A take is per locale.** If the script changes, `textHash` no longer matches
  and the take is marked stale, the same rule as `sourceHash`.

### 3.4 Narrated playback is compiled, not improvised

A new pure function in `packages/animation-engine/src/narration.ts`:

```
compileNarratedPlayback(timeline: CompiledTimeline, cues, locale, opts)
  → { segments: [{ startMs, animationEndMs, narration?: {assetId, startMs, endMs} , advanceAtMs }] }
advanceAtMs = max(animationEndMs, narrationEndMs) + gapMs
```

- `presentation.playback?: { mode: "manual" | "narrated", gapMs?: number }` in
  the document. `narrated` auto-advances clicks and slides at `advanceAtMs`.
  Manual mode still plays a step's narration when that step is reached.
- **Seek parity carries over.** The audio element's `currentTime` is *set* from
  the compiled schedule on every seek (`t - narration.startMs`), never advanced
  independently. Playing to `t` and seeking to `t` produce the same audio
  position. Add a case to `tests/playback.test.ts`.
- **Present mode:** the audience window plays audio (it is already the
  authority). `presentSync` gains a `mute` command and `state.narrationAt`. The
  presenter view shows the current cue's script and time left in the cue.
- **Reduced motion does not silence narration.** Narration is content, not
  motion. It does collapse animation time, and the schedule uses the compiled
  (reduced) animation durations.

### 3.5 Sound effects

- **Where they live:** `slide.soundCues?: SoundCue[]` with
  `{ id, source: {assetId} | {library: "whoosh-soft"}, trigger: AnimationTrigger,
  startMs, volume }`. They reuse `AnimationTrigger` and `triggerTime()`, so a
  sound can fire "with the click that reveals B". Sound cues are not animation
  tracks: they have no target element, and forcing them into tracks would
  break `W136` overlap logic.
- **Library:** `packages/renderer/src/sound-library.ts` plus about 30 short CC0
  clips (whoosh, pop, click, chime, swoosh, success, typing, applause). Ship
  them as files, list them in `apps/desktop/scripts/notices.mjs` under
  `VENDORED` with their licence and source, and keep them under 2 MB in total.
  Library sounds are referenced by name and resolved at play time; they do not
  become workspace assets.
- **The person's own audio:** uploaded through the existing begin/PUT/complete
  path (`client.assets.upload`). Extend the upload content-type allowlist in
  `apps/api/deckastra_api/assets.py` to `audio/mpeg`, `audio/ogg`, `audio/wav`,
  `audio/webm`, `audio/mp4`. Record the duration on the asset: add a
  `duration_ms` column and a migration.
- **Recording in the app:** `MediaRecorder` in a "Record narration" button. On
  desktop, the main process's permission handler must grant `media`
  (microphone only) to the editor window's main frame, following
  `main/ipc-guard.ts` rules. Render hosts and presenter windows keep refusing.

### 3.6 Timeline UI

`TimelineLanes.tsx` gets an **Audio** lane group under the element tracks:

- a narration lane: one bar per cue, positioned by the compiled schedule, with
  the waveform drawn from peaks computed once at upload and stored on the asset
  row (`waveform_peaks` JSON, 256 buckets);
- a sound lane: one bar per sound cue, draggable. Dragging writes `startMs` as an
  offset from its trigger, the same rule clips follow
  (`timeline/edits.ts`).
- Narration bars are not draggable in time (the step decides when they start),
  but they can be trimmed with `gainDb` and swapped for another take.

Every gesture is one patch with ordinary undo. There is no local timeline state.

### 3.7 Translation service

- **Backend:** `apps/api/deckastra_api/translation.py` plus routes in `routes.py`:
  - `POST /v1/presentations/{id}/locales` `{locale}` adds an empty overlay;
  - `POST /v1/presentations/{id}/locales/{locale}/translate`
    `{scope: "missing" | "outdated" | slideIds, expected_version_id}` builds the
    entries and returns them **as a proposal** (`create_proposal`). Risk is
    computed from the operations: many entries means pending for human review.
    That is the "agents propose, humans approve" rule.
- **Providers,** chosen explicitly, like `router.selected_provider()`:
  1. Cloud Translation API v3 (Advanced), with a **glossary** per workspace for
     brand terms that must not be translated. Cheap, deterministic, good for
     body text.
  2. Gemini through Vertex AI: rewrites for fit ("≤ 18 characters"), tone, and
     marketing copy. Structured output, validated with Pydantic, as
     `ask_model` already does.
  3. Local: Gemma 4 (see 02) or IndicTrans2 through the model-server supervisor.
     Nothing leaves the machine.
  A missing provider is a 503 that names what is missing. It never falls back
  silently.
- **Fit-aware translation:** the request carries each slot's character budget,
  derived from box width ÷ average glyph advance at the applied font size. The
  model is asked for a short alternative when it goes over. The final
  judgement is the render-time overflow check, not the budget.
- **Protected spans:** numbers, URLs, code spans, `{{placeholders}}` and glossary
  terms are masked before translation and restored after. Masking is plain
  code, and a test round-trips every one.
- **Untrusted content:** slide text sent to a model goes through `envelope()`.

### 3.8 Speech service (text-to-speech)

- `apps/api/deckastra_api/speech.py`, route
  `POST /v1/presentations/{id}/narration/synthesize`
  `{locale, cueIds?, voice, rate, expected_version_id}`.
- Provider: **Google Cloud Text-to-Speech, Chirp 3 HD voices** (53 locales,
  including several Indian languages; SSML subset `<break>`, `<prosody>`,
  `<say-as>`, `<phoneme>`). Output: OGG Opus 48 kHz mono (small) plus an MP3
  copy only if PPTX export needs it.
- **Cache:** key = sha256(text, locale, voice, rate, provider version). An
  identical request reuses the existing asset, so re-synthesizing a 20-slide
  deck after one edit costs one clip.
- **Duration** is read from the encoded file (Ogg granule position, or MP3
  frames). The requested rate is not trusted.
- Takes are written back **as a proposal** that adds the `takes` entries and
  their asset manifest entries in one patch, like `insertImageOperations`.
- Quotas: count synthesized characters per workspace in `quotas.py` (refuse
  first, charge after).
- Voices list endpoint: `GET /v1/speech/voices?locale=`, cached for a day.

### 3.9 Fonts and scripts

- Add to `font-library.ts` (all OFL, from `@fontsource`): Noto Sans Devanagari,
  Noto Serif Devanagari, Mukta, Hind, Baloo 2, Noto Sans Bengali, Tamil,
  Telugu, Kannada, Malayalam, Gujarati, Gurmukhi, Oriya, Noto Sans Arabic,
  Noto Naskh Arabic, Noto Sans JP, Noto Sans KR and Noto Sans SC.
  **CJK faces are large.** Ship JP/KR/SC as downloadable language packs (see 04
  §7), not in the installer.
- `resolveFontStack` (`renderer/src/fonts.ts`) appends a per-script fallback
  chosen from the locale, so Latin headings keep their family and Devanagari
  falls to Noto Sans Devanagari rather than to the OS.
- Script typography rules as data, in `renderer/src/script-rules.ts`:
  - line height ×1.25 for Indic scripts (vowel marks above and below);
  - no `text-transform: uppercase` (it does nothing);
  - no synthetic italic for Devanagari, Arabic or CJK;
  - `direction: rtl` and mirrored alignment for Arabic, Urdu and Hebrew.
- The estimator (`text-metrics.ts`) is calibrated on Latin. For non-Latin text,
  mark results `estimated: true` and rely on the browser measurer (the editor
  and exports already use it). Do **not** try to calibrate Indic widths in the
  table.
- `apps/worker/src/fonts.ts` declares the script faces a deck's *locale* needs,
  so exports embed them.

### 3.10 Exports

| Format | Locale | Narration and sound |
| --- | --- | --- |
| PDF | `locale` parameter, applied before the scene build | Dropped, and reported: "audio cannot be carried by PDF" |
| PPTX | same | Embed narration as `p:audio` media parts with timing on the click sequence (`export-pptx/src/media.ts`, `timing.ts`). Library sounds are embedded as media. Report anything approximated. |
| Video (doc 04 §35, future) | per locale | Worker renders frames at a fixed step, and ffmpeg mixes narration and sound from the same compiled schedule. This is what `scope: "presentation"` was reserved for. |

`POST …/exports` gets `locale`. The export row records it, and the degradation
report names the locale.

### 3.11 Agents and MCP

- MCP tools (`apps/mcp-server/src/tools.ts`):
  - `locale_list`: locales and their counts;
  - `locale_propose`: caller-authored entries become a proposal, and no model
    call is made on our side (the rule from `POST …/proposals`);
  - `narration_propose`: cue text only; synthesis stays a server action.
  No tool takes a path or chooses a risk tier.
- The Ask agent's prompt (`agents/deckastra_agents/prompts`) learns that
  translating means writing overlay entries, never replacing source text.

## 7. Risks

- **Overflow in long languages.** Shrink-to-fit plus Design Check make it
  visible; the short-alternative request reduces it. It will not remove it.
- **TTS pronunciation of brand names.** Use a per-workspace `<phoneme>` or
  `<sub>` lexicon applied at synthesis time.
- **Autoplay policy.** Browsers block audio without a gesture. Presenting starts
  from a click, so the first step is always user-initiated. The web share view
  needs a "Play with sound" button.
- **Deck size.** Narration in 20 languages is roughly 20 × 1 MB per 10 minutes
  in Opus. Keep takes as assets (deduplicated and ref-counted), never inline.
